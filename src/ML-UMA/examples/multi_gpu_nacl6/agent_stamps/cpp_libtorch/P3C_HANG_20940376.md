## Root cause

`LibtorchMpRuntime::~LibtorchMpRuntime` did **per-rank** `write(cmd=0) → waitpid`.  
NCCL teardown requires **all** ranks to enter `ncclCommDestroy`. Rank0 entered destroy; parent blocked on `waitpid(rank0)` before sending shutdown to rank1 → **classic teardown deadlock**.

This is **not** a missing mid-step barrier on rank1 during forward (compute path completed once).

## Fix

1. Broadcast `cmd=0` to **all** workers, then `waitpid` all (bounded + `SIGKILL` fallback).
2. `release_nccl`: control-plane rendezvous before `ncclCommDestroy`.
